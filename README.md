# プロジェクト名

## Overview
このプロジェクトは異世界を覗く体験を作成する。
具体的にはスマートフォンで景色を写すとスマートフォンに現実世界をベースに異世界風の景色が映し出されます。
フロントエンドでReact+Typescriptでバックエンドの処理をもとに画像処理を行います。
バックエンド側の処理はFastAPIを使用しフロントエンドからの画像を機械学習を使用して加工に必要な情報をフロントエンドに返します。


---

## Concept
本プロジェクトは「スマートフォンを異世界を覗く窓にする」ことを目的としています。

この体験を成立させるためには以下が必要になります：

- 現実の風景と遅延なく同期すること
- 視覚的に違和感のないエフェクト表現
- 歩きながら利用できるリアルタイム性

そのため、本プロジェクトではリアルタイム処理と描画性能を重視した設計を採用しています。
---

## Problem

現状の風景体験には以下の課題がある

- 日常の風景は情報的な変化が少なく探索体験としての面白さが弱い
- リアルタイムで風景に追従させるような変換する技術的ハードルが高い
- ARはまだまだ身近な存在ではなく誰でも手軽に動かせる体験が少ない

本プロジェクトではこれらを解決し、
「日常を探索対象に変える体験」を提供する

### 処理フロー
1. フロントエンドでカメラの画像を取得

4. 結果を返却

### 設計方針
このプロダクトの最も重要な点は現実の風景と画面に映し出される景色がシンクロすることで、スマートフォンを異なる世界を覗く窓のように扱うことである。
画像処理のすべてをバックエンド側で処理するのではなく、アプリケーションの中でも重い処理をバックエンド側で行い、画像処理はフロントエンド側で処理する。
異なる世界「風」の映像を作ることが目的であるためバックエンド側でも精度の高い処理は求めずフロントエンドでの処理で必要な品質とする。
- フロントエンド
  - 撮影した映像のバックエンドへ送信する
  - バックエンドでの処理結果をもとに撮影した映像にエフェクトなどを付与し異世界風の映像を作成する
- バックエンド
  - 機械学習モデルなどの重たい処理を行う

## Technical Decisions（技術選定の理由）

- なぜこの技術を選んだのか
  - WebRTCを採用
    - 歩きながらリアルタイムに異世界を見るという体験には低遅延が必須
    - Websocketと比較して映像などのメディアのストリーミングに最適化されている
    - デメリットとして実装コストは高いが、体験の品質を優先
  - WebGLを使用 → 描画負荷をクライアントに分散
    - すべての処理をバックエンド側で処理させるのではなく処理の一部をフロントエンドに分散することでバックエンド側の負担の軽減と画像処理をユーザーの近くで処理を行うことによるリアルタイム性の確保を目的としている。
    - フロントエンド側に処理の一部を行わせているため端末の計算能力が求められる。

## Features / 工夫点

### 処理最適化
- 深度推定を全フレームではなく間引き処理することでリアルタイム性を確保
- 描画の完全性はそこまで求めていないため処理する解像度を192×192と低解像度で処理を行う

### 描画設計
- WebGLを使用しGPUでエフェクト処理を実施
- パーティクル表現をシェーダーで実装

## Challenges（課題）
- フロントエンド側に描画するもの
  - 現在は元の映像、深度推定を行った結果の映像、WebGLによる処理を行ったものを並べているが、開発のしやすさという面ではよいが異世界を覗く窓としての雰囲気ではない
  - WebGLの処理によるエフェクトの追加の品質が理想とする幻想的な雰囲気ではない
    - 単純なノイズ表現では幻想的な雰囲気というよりはバックスクリーンのような印象となってしまうため、粒子のサイズや動きなどの設計が重要である
- バックエンド側の処理
  - 現在は深度探索のみだが、セマンティックセグメンテーションを追加することで画像内の要素ごとに描画するものを変え、より別世界感を増やす
- 深度推定の精度と速度のトレードオフ
  - 高精度モデルではリアルタイム性が失われる
  - 軽量モデルを採用し、フロント側の演出で補完する設計とした
